## ✨ Why StoryBlue Exists

Storyline development has a planning problem. Most IDs open Storyline before they've answered:

- Which variables do I need, and what are they called?
- What triggers go on which slide, in what order?
- Does my branching have dead ends? Missing feedback? Theory violations?
- Does this design actually follow Gagné, or am I just calling it Gagné?

**StoryBlue solves the pre-authoring gap.** It runs a 5-stage AI pipeline that turns a rough storyboard into a complete, validated, copyable blueprint — before you open Storyline. Every decision is made and documented. Every variable is named. Every trigger is written. Every branch path is checked.

One HTML file. No install. No server. No account.

## 🔁 The 5-Stage Pipeline

```
  STORYBOARD TEXT
       │
       ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Stage 1 — INGEST          Analyse quality, detect interactions,    │
│                             confirm it's ready to plan              │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ auto-advances on pass
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Stage 2 — SLIDE PLAN MAP  Scene/slide map · interaction types ·    │
│                             layer counts · branch flags · theory    │
│                             tags · Gagné coverage chart             │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ editable before proceeding
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Stage 3 — VARIABLES &     Named variable register (n/b/s prefix)   │
│            TRIGGERS        Full trigger architecture per slide       │
│                             Token-efficient: only slides that need  │
│                             variables, interactions, or branching   │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ editable before proceeding
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Stage 4 — BRANCHING       You confirm path destinations first.     │
│            VALIDATOR       AI checks: dead ends · missing feedback  │
│                             orphaned slides · theory violations     │
│                             BLOCK / WARN / NOTE severity levels     │
└──────────────────────────────────┬──────────────────────────────────┘
                                   │ export gated on 0 BLOCKs
                                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Stage 5 — EXPORT          6-tab blueprint document:                │
│            BLUEPRINT       Overview · Slide Map · Variables ·       │
│                             Triggers · Validation · Build Checklist │
│                             Copy per section · Copy All · Download  │
└─────────────────────────────────────────────────────────────────────┘
       │
       ▼
  OPEN STORYLINE 360
```

## ⚡ Quick Start

**1. Download the tool**

```
storyline-blueprint.html   ← this is the entire tool
```

**2. Open in Chrome or Edge** (local file — no server needed)

**3. Add your API key** → click Settings → paste key

**4. Paste your storyboard** → select a theory → click **Analyse Storyboard**

**5. Walk through all 5 stages** → copy or download your blueprint

> ⚠️ **Open the downloaded file directly in your browser — not inside a preview frame or iframe.** API calls are blocked in sandboxed previews.

## 🎬 See It in Action

Here's what Stage 4 (Branching Validator) catches on a real storyboard:

```
✗ BLOCK: THEORY VIOLATION  [S2.2]
  Branch node S2.2 is tagged as BRANCH_3PATH but declares 0 paths.
  Fix: Declare 3 destination paths for S2.2.

⚠ WARN: MISSING RETURN  [S2.4, S2.7, S2.8]
  Slides S2.4, S2.7, S2.8 appear to be branch endpoints but have no
  documented path that returns to the main flow at S2.6.
  Fix: Add 'Jump to slide' triggers that rejoin at S2.6.

ℹ NOTE: MISSING FEEDBACK  [S2.2]
  Branch node S2.2 is a SCENARIO slide but no immediate feedback slide
  is explicitly labelled.
  Fix: Rename consequence slides to include 'Feedback' in their titles.
```

**Export gate:** The pipeline won't let you proceed to Export until all BLOCK issues are resolved. WARN and NOTE issues proceed with a flag.

## 📐 Storyline Variable Naming

StoryBlue enforces Storyline 360 best-practice naming throughout all stages:

```
n prefix  →  Number      nQuizScore, nAttempts_Q1, nDecisionCount
b prefix  →  True/False  bScenarioPassed, bVisited_S3, bQuizPassed
s prefix  →  Text        sUserChoice, sLastAnswer, sSelectedPath

Rules: camelCase · no spaces · underscore for grouping context
```

Every variable in the register shows: name · type · default value · scope · used-in slides · purpose.

## ⚠️ Known Limitations

| Limitation | Detail |
|------------|--------|
| **Download in preview** | The download button is blocked in sandboxed preview frames. Open the file directly in a browser tab. |
| **No persistence** | Pipeline state lives in memory — refreshing resets everything. By design. |
| **Large storyboards** | Very long storyboards (>5,000 words) may approach token limits. Split into scenes if needed. |
| **CORS on Claude API** | Requires `anthropic-dangerous-direct-browser-access: true` header — already set in the tool. |
